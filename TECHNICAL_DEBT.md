# Technical Debt

## Hardcoded Class Definitions

Class definitions are currently hardcoded in the dataset registry.

The class names and descriptions are not consistently derived from the source dataset metadata, nor are the descriptions produced through a systematic enrichment process. This creates a risk that the semantic information provided to zero-shot classifiers may be incomplete, inconsistent, inaccurate, or unintentionally biased.

This is especially important because some classifiers, such as Emissary and generative LLM-based classifiers, rely directly on class names and descriptions to understand the decision space. As a result, manually written or mechanically generated descriptions can materially affect benchmark performance.

The current implementation is acceptable for smoke tests and interface validation, but it should not be treated as the final source of truth for a formal benchmark.

A future revision should:

- use canonical class names from the original dataset; Or generated by llms.
- load official descriptions when the dataset provides them;
- define a reproducible enrichment process when descriptions are missing;
- preserve the original labels separately from any human- or model-generated descriptions;
- version the final class definitions used in each benchmark run.
